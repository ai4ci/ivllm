# `setup-resilience/` — making the NCCL pin unavoidable

**Status: prototype, nothing built into `src/`.** The one script here is an
executable experiment, not a proposed patch. See `AGENTS.md`: scripts in
`design/` are instructional examples and must be rewritten for production.

```bash
bash design/prototype/setup-resilience/stage-runner-demo.sh   # 19/19, ~1s
```

## The problem

`src/engine/lib/slurm-vllm-setup.sh` ends with a pin that exists for a
correctness reason rather than a performance one:

```bash
uv pip install --upgrade nvidia-nccl-cu12==2.30.4      # lines 388-389
```

vLLM issue [#46097](https://github.com/vllm-project/vllm/issues/46097) traces a
multi-node TP collective-desync deadlock to the bundled `nvidia-nccl-cu12`
*build*; 2.30.4 is the version verified clean on this architecture family,
including still selecting the Cassini/libfabric (cxi) transport through
`aws-ofi-nccl` (`design/prototype/nccl-probe.sh` section [7]).

It is also the last statement of a ~390-line script that turns
`set -euo pipefail` on at line 17 and then runs **eight** third-party
`git clone` / `make` / `setup.py build_ext` / `python3 -m build` /
`uv pip install` stages. Any one of them failing — a network blip, an upstream
repo move, an aarch64 compile error, a path that only exists on compute nodes —
aborts the script. The pin is silently lost, the venv looks complete, and
nothing about the resulting job hints that the NCCL build in use is the one
documented to deadlock under sustained multi-node load.

Demonstrated by the `fragile` mode: with one optional stage broken, the script
exits 1 and the pin never runs. (`fragile` also shows the failure arriving one
stage *earlier* than the one being tested — the fused-MoE glob at line 141 is
itself a landmine, see below.)

## Why the obvious wrapper is not enough

The reflex fix is "run optional stages with `set -e` off". Measured, four ways
(`stage-runner-demo.sh` `naive` mode, and a throwaway experiment):

| Shape | Result |
| --- | --- |
| `( body ) \|\| rc=$?` | **Swallows mid-body failures.** `set -e` is ignored in a subshell created for a guarded command, and re-asserting it *inside* the subshell does not restore it (POSIX-mandated, and confirmed here). |
| `( body ) & wait $pid` | **Worse: returns `rc=0` for a failed job.** Silent success, generated by the containment mechanism itself. |
| `bash -c 'set -euo pipefail; body'` | **Correct.** A fresh process has genuine errexit, so a failure anywhere inside it aborts it, and it cannot abort the parent. |
| plain `( body )` | Same as row 1 — errexit is inherited-as-ignored. |

And with the *correct* containment, the naive version still lies. `naive` mode
breaks four optional stages in three different ways and reports:

```
naive report: failed=[deepgemm]
```

That is **two false negatives and one false positive out of four stages**:

- *False negative 1 — fused-MoE:* `cp` fails on a literal glob, the loop keeps
  going (errexit is off), `popd` succeeds, the function returns 0.
- *False negative 2 — UCCL:* `uv pip install uccl-…whl` fails, the very next
  `uv pip install deep_ep_wrapper` succeeds, the function returns 0. **A stage's
  exit status is only ever its last command's status.**
- *False positive — DeepGEMM:* no `DEEPGEMM_GIT_REF` for that release is a
  legitimate "not applicable", but exit 77 is indistinguishable from failure
  when the only signal is the exit code.

So containment alone buys "the script survives"; it does **not** buy "the report
is true". Both are needed, and they are separate mechanisms.

## What actually works

Two independent layers, both demonstrated in `resilient` mode:

**1. Containment, per stage, in a fresh process.** Use
`bash -c 'set -euo pipefail; body'` — or, better in production,
`bash "$0" --stage "$name"` re-executing the same script. The re-exec variant is
preferable because it re-sources `common-env.sh`, so the stage's environment
dies with it and there is no need to `export -f` every stage body.

Containment is not merely about surviving: the UCCL and NIXL stages `export`
`CPATH`, `CPLUS_INCLUDE_PATH`, `LIBRARY_PATH`, `LD_LIBRARY_PATH`,
`TORCH_CUDA_ARCH_LIST`, `USE_LIBFABRIC_CXI`, `UCCL_STAGING_DIR`, and `pushd`
without a matching `popd` on their failure paths. Letting those leak into the
process that then installs the NCCL pin is a correctness hazard, not a tidiness
problem. Containment additionally catches a `set -u` unbound-variable trip,
which is *fatal* to a non-interactive shell and is **not** excused by errexit
being off.

**2. A post-condition per stage — the authoritative pass/fail.** Ask the
question that matters ("is `uccl` installed?"), not "did the recipe exit
cleanly?". This is not new machinery: the script *already* opens every optional
block with exactly that probe as its "already installed, skip" guard. Reusing
the same expression after the stage runs makes one predicate serve as skip-test,
success-test and retry-test simultaneously.

| Stage | Existing guard (line) — reuse verbatim as post-condition |
| --- | --- |
| rdma-core headers | `[ -f $rdma_install_dir/include/infiniband/verbs.h ]` (64) — already a post-condition, not an existence-of-marker hack |
| fused-MoE H200→GH200 configs | `compgen -G "$configs/*device_name=NVIDIA_GH200*"` (no guard today, 138-145) |
| flashinfer-jit-cache | `uv pip show flashinfer-jit-cache` (156) |
| DeepGEMM | `uv pip show deep_gemm` (166) |
| UCCL-EP | `uv pip show uccl` / `uv pip show deep-ep` (200) |
| NIXL | `uv pip show nixl-cu12` (200) |
| humming | `uv pip show humming-kernels` (346) |
| hpc-ops | `uv pip show hpc` (358) |

Three outcomes, not two: **ok** (post-condition holds), **skipped** (the stage
declared itself not applicable — conventional `return 77`, post-condition not
asserted; this is what DeepGEMM does when a release pins no ref), **failed**
(body aborted, or body exited 0 but the post-condition does not hold). Only
**failed** belongs in the summary, and only failures make the run exit non-zero.
A clean run with three skips must exit 0 — `resilient` asserts that too.

Mandatory stages (`nvhpc` install at 44-59; `uv venv` at 125 plus
`uv pip install vllm==…` at 130-133) keep `set -e` live and abort immediately: a venv without an
importable `vllm` must never reach a success exit code, and pinning NCCL inside
it would be theatre.

**The pin then runs unconditionally, last**, followed by a one-line verification
(`uv pip show nvidia-nccl-cu12`) so a resolver downgrade cannot silently defeat
it, then the failure summary, then `exit 1` if — and only if — something is
genuinely missing. `ivllm-setup.sh` already propagates the exit code
(`IsambardBareMetalBackend.ts:85` surfaces it), so a red-but-informative result
reaches the user unchanged.

## The three landmines

Each is a single statement that aborts the whole script even when its stage is
*meant* to be optional. All three reproduced (`landmine-{1,2,3}` modes); each
asserted to abort a real child script **before** reaching the guard on the very
next line.

1. **Line 169** — `deepGEMMRef=$(curl -fsSL … | grep … | head -n 1 | sed …)`.
   An assignment takes the exit status of its command substitution, so `grep`
   finding no match returns 1, `pipefail` propagates it, and `set -e` kills the
   script *before* the `[[ -z ${deepGEMMRef:-} ]]` guard on line 171 can do its
   intended job. Two independent triggers on the same line: the SIGPIPE variant
   (`head -n 1` closing the pipe early, `grep` dying on 141) is real but
   timing-dependent and deliberately **not** reproduced here — the
   no-match variant is deterministic and sufficient. Fix: drop `head`
   (`sed -n '1p;s@…@…@p'`) and add `|| true`.
2. **Line 154** — `export FLASHINFER=$(uv pip list --format=json | jq …)`. When
   that vLLM version has no `flashinfer-python` dependency, `jq` prints nothing,
   and line 160 runs `uv pip install flashinfer-jit-cache==""` — an install that
   cannot succeed. Needs `[ -n "$FLASHINFER" ]` to **skip**, not to attempt.
3. **Line 141** — `for f in *device_name=NVIDIA_H200*` with `nullglob` unset: a
   non-matching glob stays literal, `cp` fails, and this sits inside the
   **mandatory** Phase B block, so it takes the install down with it. Fix:
   `shopt -s nullglob`.

*(A fourth, `if git clone …; then` at lines 68 and 224, is not a landmine but
the illusion of one: `if` suspends errexit for its **condition only**, never its
body — so every command inside those bodies is still live-fatal. Line 87's
`cp -rL include/infiniband/*` is inside a guarded block and still kills the run.)*

## Separate bug: retries do not re-run anything

Line 110 gates all of Phase B on `-f "$vllmVersionDir/bin/activate"` — a file
`uv venv` creates **before** line 130 installs the wheels. Die anywhere at or
after 130 and the venv exists with no vLLM in it, so every subsequent
`ivllm setup <version>` prints "already installed — skipping" and installs
nothing. `ivllm-setup.sh:64` carries the identical check, and `-r` only bypasses
the *login-node* copy; the compute-side line 110 still skips.

Gate Phase B on the payload (`uv pip show vllm`, i.e. the same post-condition
pattern) rather than on `bin/activate`. Once every stage is post-condition
gated, "which stages still need doing" stops being a separate question from
"did the last stage work", and retry becomes correct for free.

## Wiring notes for whoever productionises this

- Re-exec (`bash "$0" --stage <name>`) needs the stage bodies dispatchable
  before the main flow, and the values they close over — `workingDir`,
  `vllmVersionDir`, `nvhpcDir`, `rdma_install_dir` — **exported**, or passed as
  arguments. Under `set -u` a missed export fails loudly, which is the good
  outcome.
- `trap 'rm -rf "$workingDir"' EXIT` (line 38) still fires from the parent only,
  so per-stage children cannot delete the scratch directory out from under each
  other.
- Line 198's `uv pip install tomlkit nanobind wheel setuptools build pybind11
  meson-python` runs unconditionally on every invocation, including fully-warm
  retries.
- `$LOCAL_FABRIC="/opt/cray/libfabric/1.22.0"` (line 291) is hardcoded with no
  existence check; a site path change fails deep inside meson with an
  unrecognisable error. `common-env.sh:116-117` hardcodes the same path twice
  more.
- Keep `set -euo pipefail`. Everything here is about *scoping* it, not removing
  it — it is what makes the mandatory path safe.

## Test plan for the real change

Nothing currently exercises `slurm-vllm-setup.sh`. `tests/bash/shims/` already
has `uv`, `git`, `wget`, `srun` and `g++`/`gcc` shims, so a sandboxed test can
make one stage fail and assert (a) the pin still ran, (b) the failed stage is
named in the summary, (c) a *mandatory* failure still aborts before the pin.
There is **no `cmake` shim** — the rdma-core branch needs one added, or the
branch must be skipped in the sandbox. Per `AGENTS.md`, that test should be
written and shown to fail before the change lands.

## Not covered here

No timing/perf measurement, no attempt to make the builds themselves more
robust (pinning upstream refs instead of `main`, vendoring the four
`git clone`s), and no container-install-path alternative — see ADR-114 in
`design/adr.md`. The UCCL/NIXL stages clone `main` with no ref pin, so they are
the most likely stages to break and the least reproducible when they do; that is
a separate decision from this one.

The bugs above are pre-existing and unfixed (per `AGENTS.md`), and are not yet
recorded in `design/active-issues.md` — worth a one-line entry each there when
this gets actioned.
